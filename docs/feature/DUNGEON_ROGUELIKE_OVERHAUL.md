# 地牢 Roguelike 系统重构方案

> 状态：P0/P1 已完成（feature/dungeon-overhaul 分支），P2 起待实施
> 日期：2026-07-05
> 范围：`dungeon` / `dungeon_f2` 地图链路（Hub 紫色传送门进入的 Roguelike 关卡）

---

## 1. 背景与问题诊断

现有地牢（`DungeonLayoutGenerator.js` + `DungeonManager.js` + `RoomInteriorTemplates.js`）具备「BSP 切房 + 房间锁门战斗 + 两层楼 + Boss」的骨架，但体验不达标。经代码调研，问题定位如下：

### 1.1 视觉层（丑）
- 地牢墙体无专属素材：仅两色平涂（`WALL_FRONT #4a3b45` / `WALL_TOP #6d5a65`，`Renderer.js:197-210`），与 Hub/城镇共用同一墙色；地板有石砖 sprite 而墙没有任何纹理。
- F1 与 F2 地板、墙、装饰完全相同，无楼层进度感。
- 全地牢可见物件仅 6 种：掩体 3 种（box/barrel/explosive_barrel）+ 装饰 3 种（碎石/骨堆/铁笼），每房 0-3 个，极稀疏。
- 纯 BSP 矩形房 + L 形直角走廊 + 网格对齐内墙 = 「盒子套盒子」。
- 现存 bug：`Renderer.js:221-222` 读取从未赋值的 `gate.isHorizontal`（`DungeonManager.initGates` 只存 `orientation`），横向能量屏障渲染尺寸错误。

### 1.2 玩法层（无聊）
- 房间节奏单一：所有房间都是「进门→锁门→清怪→开门」，无商店/宝箱/精英/事件房。
- 掉落无深度：清房 30% 概率掉一把全池等权重随机武器（`DungeonManager._dropRoomRewards`），37 把武器掉率完全相等；`RARITY_VALUE_SYSTEM.md` 设计的 5 档稀有度从未落地（无 `src/core/economy/` 实现，全库无代码读取 rarity 字段）。
- 可破坏物（箱/桶）无任何掉落；无货币、无钥匙、无商店、无局内成长闭环。
- 敌人全部从主世界搬来：AI 清一色流场追身，无弹幕威胁轴；无精英词缀、无数值缩放；三只僵尸移动代码互为复制粘贴。
- 三个 Boss（变异巨兽/机械魔偶/机械巨蛇）各自独立实现高度雷同的相位状态机，零共享抽象；机械巨蛇 Boss 已完成但未接入任何正式流程（仅测试面板可生成）。

### 1.3 可复用的资产（重构的地基）
- `DungeonManager` 房间状态机（idle→active→cleared）、能量屏障、拓扑小地图运行时健康，保留并扩展。
- `StatusEffectSystem` 已有 10+ 种效果（燃烧/冰冻/中毒/闪电链/黑洞/吸血/钉刺/力场等），冻结易伤 1.5x 等组合技底层已通——遗物系统直接挂载。
- 37 把武器机制设计完好，问题纯在获取与成长。
- 地牢链路与未提交的城镇模板工作（`TownLayoutGenerator` 等）互相独立，无冲突。

## 2. 设计目标与非目标

### 目标
1. **核心体验对标《挺进地牢》**：房间遭遇战 + 弹幕躲避 + 「开宝箱抽新枪」的期待感。
2. 让 37 把武器与状态效果系统的价值被玩家真实感知（稀有度、宝箱、商店、遗物组合）。
3. 单局 20-30 分钟、3 层楼、难度递进、数据驱动可扩展。

### 非目标（本期不做）
- 推倒重写生成器拓扑层（BSP+MST 保留，二期再考虑洞穴形态等）。
- Meta 进度（局外永久解锁/天赋树）。
- 多主题楼层美术（单主题深挖，楼层间仅做光色与装饰配比微差异）。
- 秘密房、诅咒、武器词缀 roll（列入后续迭代候选）。

## 3. 系统架构

新增地牢专属子系统目录，横向系统数据驱动、互相解耦：

```
src/core/dungeon/
  DungeonRunState.js      # 单局状态：金币/钥匙/已获遗物/楼层进度/种子
  LootTable.js            # 稀有度加权掉落表（落地 5 档稀有度）
  RelicSystem.js          # 遗物运行时（属性聚合 + 弹道钩子 + 事件触发）
  EnemyAffixSystem.js     # 精英词缀（生成时附加，染色+强化+掉落加成）
  DungeonShop.js          # 商店房（商品生成/定价/购买交互）
  FloorConfigs.js         # 3 层数据驱动配置

src/assets/dungeon/       # 地牢专属美术（墙体/火把/宝箱/金币/钥匙/装饰/商人）
src/assets/relics/        # RelicData.js 遗物定义 + 图标绘制
src/core/entities/behaviors/  # 敌人行为组件
src/core/entities/ChestObject.js（或 objects/ 注册）  # 宝箱实体
```

关键接线：
- `WeaponData.js` 全部 37 把武器补 `rarity` 字段（common/uncommon/rare/epic/legendary，参照 `RARITY_VALUE_SYSTEM.md` 的定档）。
- `DungeonManager` 扩展：特殊房间激活逻辑、宝箱/商店房不锁门、精英房保底掉落。
- `Game.js` 注入 `DungeonRunState` 与 `RelicSystem`；进入地牢初始化、退出/死亡/通关时清算。
- 遗物三挂载点：属性聚合器（PlayerSystem/CombatSystem 读乘区）、子弹生成钩子（`CombatSystem.tryShoot` 注入弹道修改）、事件总线（onHit/onKill/onRoomClear/onChestOpen）。

## 4. 详细设计

### 4.1 关卡生成升级

拓扑层保留 BSP + 近邻 MST + 环路边，改造房间层与内容分配：

1. **手作房间模板池**：替换现有 12 种网格内墙模板。每个模板定义：
   - 非矩形地板轮廓（在包围盒内雕刻，支持凹角/斜切/内凹壁龛）
   - 掩体位、装饰位、出怪点（带类型标记：近战点/远程高台位/召唤位）
   - 适用房型与类别标签、尺寸区间
   - 首期 ≥24 个模板，按「房型 × 类别」分池加权抽取（复用现有权重减半防重复机制）
2. **特殊房间**进入拓扑分配（`assignRoomCategories` 扩展）：
   - **商店房**：每层 1 间，安全区不锁门，商人 NPC + 货架陈列
   - **宝箱房**：每层 1 间（替代现 reward 房），放置 1-2 个分级宝箱
   - **精英房**：每层 1 间，词缀怪小队 + 保底钥匙 + 品质加成掉落
   - 保留：起始房（EXIT 门）、Boss 房、普通战斗房
3. **楼层配置**（`FloorConfigs.js`）：每层定义房间数量、敌人池与权重、精英预算、掉落品质权重、Boss 类型、商店商品档次。加层只需加配置。
4. **种子可复现**：生成种子记录 console，支持 URL 参数/调试面板固定种子。
5. 修复 `gate.isHorizontal` bug（渲染读 `orientation`）。

### 4.2 视觉打磨（单主题「石牢监狱」深挖）

1. **地牢专属墙体 sprite**（性价比最高）：石砖墙面 + 墙顶贴图（参照 `WallTexture.js` 的砌体纹理管线做地牢色板版本），含破损/苔藓 2-3 种变体，按 tile 位置哈希混铺。
2. **火把/吊灯氛围光**：新增 `dungeon_torch`（墙面挂饰）与 `dungeon_brazier`（火盆，可破坏），注册进 `LightEmitterRegistry` 发暖橙光；走廊与房间按间距布光。环境亮度调暗以突出光源对比。
3. **装饰库扩容 3 → 12+**：石柱/断柱、雕像、蛛网（墙角贴花）、锁链、水洼（反光贴花）、旗帜、烛台祭坛、牢栏残段、木刑架、蘑菇丛、散落书页/瓦砾变体。密度上调，按房间类别分配（如精英房配旗帜+火盆，宝箱房配祭坛+烛台）。
4. **地板细节**：现有 4 种石砖变体基础上加血迹/裂纹/苔藓贴花层；Boss 房专属地面图案（大圆环刻纹）。
5. **楼层微差异**：F1 冷蓝灰 → F2 暗绿（苔藓/毒气感）→ F3 暗红（炽热/危险感），通过火光色调、装饰配比、贴花选择实现，不做整套新素材。
6. 宝箱（4 档配色）、金币、钥匙、商人 NPC 素材，全部 PixelDraw 程序化绘制，放 `src/assets/dungeon/`。

### 4.3 经济与掉落循环

- **金币**：敌人死亡掉落（普通怪 2-5、精英 ×3、Boss 大量），金币实体靠近自动吸取（拾取半径可被遗物加成），HUD 常驻计数。可破坏物 30% 掉 1-3 金币。
- **钥匙**：清房 15% 概率、精英房保底 1 把、商店有售。HUD 显示持有数。
- **分级宝箱**（宝箱实体，交互开启）：
  | 档次 | 颜色 | 是否需钥匙 | 稀有度权重倾向 |
  |---|---|---|---|
  | 木箱 | 棕 | 否 | common 为主 |
  | 铁箱 | 蓝 | 是 | uncommon/rare |
  | 秘银箱 | 绿 | 是 | rare/epic，偏遗物 |
  | 龙纹箱 | 红 | 是 | epic/legendary，偏遗物 |
  - 产出：武器或遗物二选一随机（高档偏遗物），附带金币。
  - 分布：宝箱房 1-2 个（档次随楼层上浮）、普通房小概率木箱、Boss 掉保底绿/红箱。
- **商店房**：货架陈列 1 武器 + 2 遗物 + 1 钥匙 + 补给（medkit；弹药补给包为可选项，现有系统无弹药拾取物，若做需新增消耗品类型），按稀有度定价，E 键购买，余额不足提示。每层商品档次由 FloorConfig 控制。
- **稀有度加权掉落**（`LootTable.js`）：所有武器/遗物掉落统一走稀有度权重表抽取，档内均匀。房间清除掉落、宝箱、商店、Boss 全部接入。
- **带出规则**：金币/钥匙/遗物为单局资源（通关、死亡、主动退出即清空——`DungeonRunState` 统一清算）；武器保持现状可带回主世界（地牢 = 沙盒模式的军火库来源）。

### 4.4 遗物系统（首发 15-20 个）

定义在 `src/assets/relics/RelicData.js`，运行时 `RelicSystem.js`，三类：

1. **属性类（约 6 个）**：移速+15%、射速+20%、伤害+15%、最大 HP+25、拾取半径×2、暴击率+10%。实现为乘区聚合，PlayerSystem/CombatSystem 计算时读取。
2. **弹道改造类（约 7 个）**：子弹附燃烧、附冰冻（与冻结易伤 1.5x 天然成组合技）、+1 穿透、+1 弹射、击杀爆炸、弹丸数+1（伤害系数 0.8 补偿）、弹丸体积+50%。实现为 `tryShoot`/子弹生成钩子注入 bullet 属性——**全部复用 StatusEffectSystem 现有效果，零新战斗机制**。
3. **触发类（约 5 个）**：受击释放击退冲击波（内置 CD）、杀敌 10% 回 2 HP、HP<30% 时伤害+30% 射速+20%、清房金币翻倍、开箱 20% 双倍产出。实现为事件监听（onHit/onKill/onRoomClear/onChestOpen）。

- UI：HUD 遗物图标栏（横排小图标，悬停/长按显示说明）、拾取时全屏 toast（名称+效果描述）。
- 获取：宝箱（绿/红档主要来源）、商店购买、Boss 首杀保底。
- 同名遗物不重复掉落（`DungeonRunState.ownedRelics` 参与掉落过滤）；属性类可设计 1-2 个可叠加例外。

### 4.5 敌人重构

1. **行为组件层**（`src/core/entities/behaviors/`）：`ChaseBehavior`（现有流场追击抽出）、`KiteBehavior`（保持距离拉扯）、`StrafeBehavior`（横移走位）、`RangedPatternBehavior`（弹幕模式库：扇形散射/环形爆发/瞄准连发，数据配置）、`SummonBehavior`、`TelegraphedChargeBehavior`（地面预警线+冲锋）。新敌人 = 属性数值 + 组件组合；现有敌人本期不强制迁移（避免回归风险），仅女僵尸冲刺等可顺手抽为组件。
2. **6 种地牢专属新敌人**（每种一个威胁轴，32×32，走现有 Generator→帧→Assets 管线）：
   | 敌人 | 威胁轴 | 行为组合 |
   |---|---|---|
   | 弹幕法师 Warlock | 弹幕覆盖 | Kite + 环形/扇形弹幕 + 短距传送 |
   | 自爆蜂 Boomer | 逼走位 | 高速 Chase + 预警自爆（可被提前引爆） |
   | 召唤师 Summoner | 优先级压力 | Kite + 周期召唤 2-3 小怪（上限控制） |
   | 盾卫 Shieldbearer | 逼包抄 | 慢速推进 + 正面盾牌挡子弹（背后弱点） |
   | 哨戒炮 Sentry | 区域封锁 | 固定点 + 蓄力后持续弹流压制 |
   | 投弹手 Lobber | 反掩体 | Kite + 抛物线榴弹（落点预警圈） |
3. **精英词缀系统**（`EnemyAffixSystem.js`）：迅捷（移速+40%）、坚韧（护盾条，破盾前减伤 50%）、灼热（接触附燃烧+死亡留火圈）、裂魂（死亡弹幕爆发）、再生（脱战回血）。精英 = 基础怪 + 1-2 词缀 + 体型 1.15x + 染色 overlay + 头顶词缀名；掉落金币 ×3 + 钥匙概率提升。每层精英预算（普通房出现概率+精英房保底）由 FloorConfig 控制。
4. **Boss 整合**：
   - 抽取 `BossPhaseController`（相位阈值/招式加权池/冷却状态机），三个 Boss 迁移接入，新 Boss 边际成本大降。
   - 楼层顺序：**F1 变异巨兽（近战教学）→ F2 机械巨蛇（机动压迫）→ F3 机械魔偶（弹幕终战）**，机械巨蛇首次接入正式流程。
   - Boss HP/伤害/招式频率按 FloorConfig 缩放；Boss 掉落改为保底高档宝箱 + 金币堆。
5. **数值缩放**：楼层难度不再只靠换怪种，敌人 HP/伤害按层乘系数（F1 ×1.0 / F2 ×1.3 / F3 ×1.6，可调）。

## 6. 风险与对策

- **性能**：新增光源（火把）数量受 `LightingConfig` 预算管控，装饰物不参与光照遮挡（沿用户外植被的豁免策略）；金币实体高并发时用简化 update（无碰撞解析，仅吸取检测）。
- **回归**：现有敌人不强制迁移行为组件；`DungeonManager` 扩展保持对外接口不变；主世界玩法路径零改动（除 WeaponData 加字段）。
- **范围蔓延**：秘密房/武器词缀/多主题/Meta 进度明确列为非目标。
- **平衡不确定性**：所有数值集中在 FloorConfigs/LootTable/RelicData 数据文件，P6 统一调参。
