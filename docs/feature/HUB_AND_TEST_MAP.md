# 游戏大厅与测试地图功能方案 (Hub & Test Map)

## 1. 背景 (Background)
随着游戏机制的日益复杂，我们需要一个安全的环境来测试新的武器、物品和物理效果，同时也需要一个游戏内的“大厅”作为玩家的初始出生点，用于选择关卡或进行准备。

## 2. 功能概述 (Overview)
本方案旨在引入“多地图支持”，将游戏流程改为：
1. **初始进入 (Hub)**: 玩家出生在一个安全的大厅区域。
2. **传送门系统**: 大厅内设有传送门，连接到不同的游戏地图。
3. **测试地图 (Test Map)**: 一个专门用于开发测试的地图，包含所有武器和大量可破坏物体。

## 3. 详细设计 (Detailed Design)

### 3.1 大厅地图 (Hub Map)
- **环境**: 安全区域，无敌人。
- **边界**: 封闭的房间或岛屿。
- **设施**:
  - **传送门 A (Main Game)**: 传送至当前的主游戏地图（随机生成，包含大量敌人）。
  - **传送门 B (Test Map)**: 传送至测试专用地图。
  - **视觉提示**: 
    - 传送门采用正式的像素风格绘制（石制拱门 + 符文）。
    - 带有半透明的漩涡粒子效果。
    - 交互提示：靠近时显示 `[E] ENTER`。

### 3.2 测试地图 (Test Map)
**用途**: 这是一个开发者和玩家都可以使用的“靶场”和“实验室”。

**测试内容包含**:
1. **武器库 (Weapon Rack)**:
   - 自动生成游戏中定义的所有武器（`WeaponData` 中的每一项）。
   - 按顺序横向排列，方便逐一拾取测试手感、射速和特效。
2. **破坏物理场 (Destruction Grid)**:
   - **木箱阵列**: 5x5 密集排列，测试普通子弹的穿透和单体破坏。
   - **木桶阵列**: 5x5 排列，测试爆炸、连锁反应（如有）和高血量物体。
   - **花瓶阵列**: 5x5 排列，测试易碎品的破碎效果。
3. **障碍穿越测试 (Obstacle Course)**:
   - 设置了狭窄的墙缝和拐角。
   - **目的**: 验证玩家的碰撞箱 (16x16) 是否能顺滑通过视觉上看起来能通过的缝隙（测试 2.5D 碰撞逻辑）。

### 3.3 传送门机制 (Portal System)
- **触发**: 玩家靠近传送门中心（50px 范围内）并按下 **E 键**。
- **效果**: 
  1. 清空当前地图的所有实体。
  2. 重置玩家位置。
  3. 加载新地图数据。

## 4. 技术实现 (Technical Implementation)

### 4.1 数据结构变更
- **WorldSystem.js**:
  - 支持 `loadMap(mapType)` 切换逻辑。
  - 动态生成测试场的物品网格。

### 4.2 实体与碰撞
- **Portal.js**: 包含粒子系统和交互检测逻辑。
- **碰撞逻辑**: 
  - 详见 `docs/COLLISION_GUIDE.md`。
  - 测试场中的物体完美展示了“底座碰撞”与“全身受击”的分离逻辑。

---

**已确认事项**:
1. 传送门视觉：正式像素风格 + 粒子特效。
2. 测试地图：无作弊功能（正常弹药/血量）。
3. 交互方式：按 E 键进入。
