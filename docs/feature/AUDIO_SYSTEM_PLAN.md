# 音效系统方案 —— 程序化合成音频

> 状态：已确认（2026-07-05）——音色走现代厚实混搭（枪声分层合成、UI 留芯片味）、音乐仅做氛围垫（P3）、P1 立即开工（与张力批次并行）。§4 决策点已全部拍板。
> 背景：游戏目前**完全静音**（全代码无一行音频 API）。射击游戏的手感一半在声音；这是当前最大的体验缺口之一。

## 0. 核心决策：技术路线

### 路线对比

| 路线 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| A. 外部音频文件 | 下载/购买 wav/ogg | 质感天花板高 | **违反项目"零外部素材"原则**，体积暴涨，排除 |
| B. ZzFX 式微型合成 | 每个音效 = 一行 ~20 个数字参数，运行时合成 | 极轻（引擎 <1KB 思路）、参数配方生态成熟、8-bit 质感与像素画风统一 | 音色偏"芯片"，厚重感有限；音乐要另配 tracker |
| C. 自研 Web Audio 合成器 | AudioContext 节点图：振荡器+噪声+滤波+包络，手写 SynthEngine（~300 行） | 完全可控；可做**分层音色**（低频体+中频瞬态+高频泛音），比 8-bit 厚；与 PixelDraw"手写生成器"哲学同构 | 工作量比 B 大；调音需要耐心 |

### 推荐：C 为骨架、B 为配方参考的混合路线

自研一个小合成器（`SynthEngine`），但**音效定义采用 ZzFX 式的纯参数对象**——即"引擎手写、音色数据化"。这与我们美术管线完全同构：PixelDraw（引擎）+ 每个物件一份绘制参数（数据）。参数化意味着后续调音只改数据文件、可以让 agent 批量铺音色、甚至能用 Gemini 工作流优化音色参数（类比像素画优化）。

合成器只需要五种原语，全部是 Web Audio 原生节点，无任何依赖：
1. **振荡器**（sine/square/sawtooth/triangle + 频率包络滑音）——枪声基音、UI 音、音乐音符
2. **噪声源**（白噪/预渲染噪声 AudioBuffer + 带通滤波）——爆炸、霰弹、脚步、破碎
3. **增益包络**（attack/decay/sustain/release）——一切音效的形体
4. **双二阶滤波器**（lowpass/highpass 扫频）——爆炸闷响、激光"啾"、消音感
5. **失真/削波**（WaveShaper）——重武器的"脏"和冲击感

**分层出厚度**：一声枪响 = 低频"胸腔感"正弦冲击（60-120Hz，20ms）+ 中频噪声瞬态（500-2kHz 带通，40ms）+ 高频"啪"（6kHz+，10ms）三层叠加。这是合成音效摆脱"廉价 8-bit"的关键，参数里体现为每个音效 1-3 个 layer。

## 1. 架构设计

```
src/core/audio/
  SynthEngine.js      音效合成核心：参数 → AudioBuffer（首次合成后缓存复用，避免每次建图+GC）
  SoundSystem.js      运行时：AudioContext 生命周期/解锁、主总线、播放调度、节流、音量设置
  MusicDirector.js    （P3）分层氛围/BGM 状态机
src/assets/audio/
  SfxData.js          全部音效参数定义（纯数据，类比 WeaponData；每条含 layers/pitch 随机抖动）
  WeaponSfxMap.js     武器 id → 音色 id + 参数微调（36 把枪按 8-10 个基音色族+个性偏移）
  MusicData.js        （P3）音序/和弦进行数据
```

### SoundSystem 关键设计

- **解锁**：AudioContext 必须在用户手势内 resume——桌面挂 keydown/mousedown 一次性监听，移动端挂 MobileControls 的首个 touchend。解锁前的播放请求直接丢弃（不排队）。
- **总线**：master → 压缩器（DynamicsCompressor 防多音效叠加爆音）→ 目的地；sfx/music 两条子总线独立音量。
- **节流**（射击游戏必做，否则 SMG 每秒 12 发 × 命中音 = 轰炸）：
  - 同音效同帧去重；同音效最小重触发间隔（如 30ms）；
  - 全局最大并发 voices（如 16），超出丢最老的低优先级音；
  - 同音效连发时音量递减 + 音高随机抖动 ±5%（避免机关枪打成蜂鸣）。
- **优先级**：受击/Boss/UI > 击杀/爆炸 > 开火 > 命中 > 环境。
- **听感定位**（可选）：StereoPannerNode 按声源相对玩家 x 偏移左右声道，距离线性衰减——一行折算，白送空间感。
- **设置与持久化**：总音量/音效/音乐三滑条；localStorage 存档；入口放 HUD 简易面板（pixelOS 出设置 App 是后话）。
- **页面隐藏暂停**：visibilitychange 时 suspend/resume。

## 2. 工程分期（大工程拆小，每期独立可交付）

- **P1 引擎+高频音效（一个 agent 批次可完成）**：SynthEngine + SoundSystem + SfxData ~25 条 + WeaponSfxMap 按 10 个音色族覆盖 36 枪 + 上表接线。验收：实机开一局，射击/命中/击杀/拾取/受击全程有声且不轰耳。
- **P2 内容语音层**：敌人攻击前摇音（扑击蓄力嘶吼=听觉预警，直接服务"危机感"）、敌人受击/死亡按类别细分、Boss 每技能专属音、三种新房型事件音（倒计时滴答、契约拉杆、猎杀逃遁）、环境点缀（火把噼啪、水滴）。
- **P3 音乐与混音**：楼层氛围垫（低频 drone + 稀疏打击，按 F1/F2/F3 主题变调）、战斗/探索双状态过渡、爆炸时 ducking（侧链压低其他声）、整体响度平衡 pass。BGM 走音序数据（MusicData 定义音符/和弦进行，MusicDirector 调度）——依然零外部文件。

## 3. 风险与对策

| 风险 | 对策 |
|---|---|
| iOS/安卓不出声 | 手势解锁 + suspend/resume 生命周期；上线后真机（你的手机）验证一次 |
| 音效轰炸疲劳 | 节流三件套（去重/并发上限/递减抖动）从 P1 就内建，不是后补 |
| 合成音色廉价感 | 分层合成是底线要求；每条音效 ≥2 层；验收标准"闭眼听不出是数学生成的" |
| 性能（移动端） | 预渲染 AudioBuffer 缓存（合成一次永久复用）；节点图播放开销可忽略 |
| 调音无止境 | 参数数据化，先铺量后精修；主观验收由用户实机拍板 |

## 4. 决策点（待用户确认）

1. **音色气质**：偏 8-bit 复古芯片音（更"像素"）还是分层合成的现代厚实音（更"射击手感"）？——方案默认后者，枪声厚、UI 音保留一点芯片味的混搭。
2. **音乐范围**：P3 的 BGM 做不做？只做氛围垫（低成本高氛围）还是完整旋律 BGM（工作量翻倍）？
3. **分期节奏**：P1 现在就开工（与张力批次并行，文件几乎零冲突），还是等张力批次验收完再上？
