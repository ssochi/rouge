# 载具系统方案 (Drivable Vehicle System)

## 1. 美术风格分析与决策 (Art Style Analysis & Decision)

### 1.1 竞品分析 (Benchmark)
在 2.5D Top-Down Shooter 游戏中，载具的表现形式主要有两种：

1.  **完全俯视 (Pure Top-Down)**
    *   **代表作**: *GTA 1/2*, *Hotline Miami* (部分车辆), 早期 Flash 游戏。
    *   **特点**: 车顶完全可见，看不到侧面。支持 360 度自由旋转。
    *   **优点**: 逻辑实现简单，旋转自然。
    *   **缺点**: 缺乏立体感，与 2.5D 角色（能看到正面/侧面）风格不统一。

2.  **伪 3D / 2.5D 旋转 (Fake 3D Rotation)**
    *   **代表作**: *Enter the Gungeon* (矿车/特殊载具), *Nuclear Throne* (废车), *Metal Slug* (坦克)。
    *   **特点**: 车辆有多个朝向的 Sprite（通常 8 或 16 方向）。
    *   **优点**: 立体感强，完美契合 2.5D 场景。
    *   **缺点**: 制作成本极高（需要画多个角度），或者需要 3D 模型转 2D Sprite。

### 1.2 本项目决策 (Decision)
鉴于我们的项目是 **像素风 2.5D 俯视视角**（能看到角色的脸和身体），如果车辆采用“完全俯视（只能看到车顶）”，确实会产生**视觉违和感**（Paper Thin 纸片感）。

但考虑到我们目前没有 3D 引擎支持，且手绘 16 方向的车辆 Sprite 成本过高，我提出一种 **“2.5D 堆叠切片 (Stacked Sprite / Voxel-like)”** 的折中方案，或者称为 **“带透视的伪 3D 旋转”**。

**方案：Top-Down with Fake Height (伪高度俯视)**
- **核心逻辑**: 依然使用 Top-Down 的旋转逻辑（代码控制 `angle`）。
- **美术欺骗**:
  - **车身**: 不仅仅画一个矩形，而是画一个带有“厚度”的矩形（车顶 + 后保险杠/引擎盖的透视面）。
  - **阴影**: 强制在车身下方绘制偏移阴影，营造悬浮感/立体感。
  - **车轮**: 车轮独立绘制，且在旋转时，车轮相对于车身的偏移量会根据角度进行微调（模拟透视变化，虽然代码实现较复杂，但第一版我们可以先做简单的固定偏移）。

**修正后的美术表现**:
- 我们不画纯平面的车顶。
- 我们画一个**略带后方透视的车顶**（能看到一点点车尾）。
- 当车辆旋转时，虽然本质上还是在旋转一张图片，但配合像素风格和阴影，这种“纸片旋转”在快节奏游戏中是可以接受的（参考 *Hotline Miami* 的汽车，虽然是 Top-Down，但车是有侧面细节的）。

## 2. 核心功能 (Core Features)

### 2.1 交互 (Interaction)
- **上车**:
  - 玩家靠近车辆（50px 范围）。
  - 提示 `[E] DRIVE`。
  - 按 `E` 键后，玩家角色隐藏（或变为“驾驶中”状态），摄像机焦点平滑切换至车辆。
  - 控制权转移至车辆。
- **下车**:
  - 车辆静止或低速时。
  - 按 `E` 键，玩家在驾驶位旁生成。
  - 摄像机焦点切回玩家。
  - 控制权转移至玩家。

### 2.2 驾驶物理 (Driving Physics)
- **控制方式**: `WASD`
  - `W`: 加速 (Throttle)
  - `S`: 刹车/倒车 (Brake/Reverse)
  - `A/D`: 转向 (Steering)
- **物理特性**:
  - **惯性与摩擦**: 车辆松开油门后会滑行一段距离。
  - **转向**: 只有在车辆移动时才能有效转向（或原地极其缓慢转向）。
  - **倒车**: 倒车时转向反向（符合真实驾驶逻辑）。
  - **碰撞**: 车辆具有物理碰撞体，撞墙会反弹并产生碰撞效果。

## 3. 美术具体实现 (Visual Implementation Details)

### 3.1 车辆结构 (Vehicle Structure)
我们将使用 `PixelDraw` 动态绘制以下部分：

1.  **阴影层 (Shadow)**: 一个半透明黑色圆角矩形，略微偏移，提供悬浮感。
2.  **车轮层 (Wheels)**:
    - 4 个黑色圆角矩形。
    - 前轮根据 `steeringAngle` 旋转。
    - 位置固定在车身四角。
3.  **底盘层 (Chassis)**: 深色矩形，略大于车身，模拟保险杠和侧裙。
4.  **车身层 (Body)**: 主色调（如军绿色或深蓝色）。
5.  **车顶层 (Roof)**: 较浅色调，略微向后偏移，模拟高度差（Pseudo-3D）。
6.  **车窗 (Windows)**: 浅蓝色块。

### 3.2 动态效果
- **尾气**: 车辆行驶时车尾生成粒子。
- **轮胎印**: 急转弯或刹车时在地面留下痕迹（可选）。

## 4. 技术实现 (Technical Implementation)

### 4.1 新增类
- **`src/core/entities/Vehicle.js`**:
  - 属性: `x`, `y`, `angle` (朝向), `speed`, `steeringAngle` (前轮角度).
  - 配置: `maxSpeed`, `acceleration`, `friction`, `turnSpeed`.
  - 方法: `update()`, `draw()`, `enter(player)`, `exit()`.

### 4.2 系统集成
- **`PlayerSystem.js`**: 处理上车逻辑，当玩家状态变为 `driving` 时，暂停玩家的常规移动更新。
- **`Game.js`**: 
  - 主循环中需要判断当前控制对象是 Player 还是 Vehicle。
  - 摄像机 (`Camera.js`) 需要支持跟随 Vehicle。

### 4.3 碰撞与战斗系统 (Collision & Combat)

#### 碰撞逻辑 (Collision Logic)
- **阻挡规则 (Blocking)**:
  - 车辆会被 **墙壁 (Walls)**、**不可破坏物体**、**敌人 (Enemies)** 和 **玩家 (Player)** 阻挡。
  - **例外**: 如果车辆的速度足够快（Ramming Speed）且目标的生命值低于撞击伤害，车辆将**直接摧毁**目标并继续移动，不会被阻挡。
- **碾压伤害 (Ramming Damage)**:
  - 车辆高速撞击物体或敌人时造成伤害（如 100点）。
  - 若目标生命值 <= 伤害值 -> 目标破碎/死亡，车辆略微减速但继续前进。
  - 若目标生命值 > 伤害值 -> 目标存活，车辆反弹/停止。

#### 生命值与破坏 (Health & Destruction)
- **车辆生命值 (Vehicle HP)**: 车辆拥有独立血条（如 200 HP）。
- **受击判定 (Damage Handling)**:
  - 玩家和怪物都可以攻击车辆。
  - **驾驶员保护 (Driver Protection)**: 当玩家在车内时，**玩家免疫所有伤害**，所有针对玩家的攻击（子弹/近战）都由车辆承担。
- **车辆销毁 (Destruction)**:
  - 当车辆 HP <= 0 时，触发 **爆炸 (Explosion)**。
  - **爆炸后果**:
    - 播放爆炸特效和音效。
    - 车辆实体消失。
    - **驾驶员伤害**: 如果玩家在车内，爆炸将扣除玩家 **高额血量** (如 50-80 HP)，并强制将玩家弹出（若玩家仍存活）。

## 5. 开发计划
1. **美术资源**: 使用 `PixelDraw` 绘制“伪 3D” SUV（车身+4个轮子）。
2. **基础移动**: 实现 WASD 控制车辆的前进和旋转。
3. **物理优化**: 加入惯性、摩擦力和倒车逻辑。
4. **交互流程**: 实现无缝上下车切换。
5. **场景投放**: 在 Test Map 中放置车辆。
